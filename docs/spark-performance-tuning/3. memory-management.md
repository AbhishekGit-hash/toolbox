| Memory Type     | When it's needed                                                                 |
|-----------------|----------------------------------------------------------------------------------|
| On-Heap Memory  | Default for all Spark operations — RDDs, DataFrames, broadcasts, shuffle buffers |
| Off-Heap Memory | Enabled with `spark.memory.offHeap.enabled=true`. Useful to reduce GC pressure on large datasets by moving storage/execution memory outside JVM control |
| Overhead        | Always present. Must be accounted for in YARN container sizing or YARN will kill the container |
| Executor Memory | Joins, Shuffles, Sorting, GroupBy. `Critical High-Priority` tasks |
| Storage Memory  | RDD, Dataframe Caching, Brodcast Variables |
| User Memory     | User Defined Data Structures: Variables, Objects |
| Reserved Memory | Always present. Must be accounted for in YARN container sizing or YARN will kill the container |


---
### 1. On-Heap Memory
---

**On-Heap Memory** = Execution Memory + Storage Memory + User Memory + Reserved Memory


**Spark Configs**

On-Heap Memory = spark.executor.memory<br>
Unified Memory = spark.memory.fraction (0.6) * On-Heap Memory<br>
Storage Memory = spark.memory.storageFraction (0.5) * Unified Memory<br>
Reserved Memory = 300 MB<br>

**Execution Memory** = Unified Memory - Storage Memory
**Unified Memory** =  Execution Memory + Storage Memory<br>
**User Memory** = Execution Memory - Unified Memory - Reserved Memory<br>

---
### 2. Off-Heap Memory
---

By practice Off-Heap Memory = 10% - 20% of spark.executor.memory<br>

Off-Heap Memory = spark.memory.offHeap.size (with spark.memory.offHeap.enabled = true)<br>

By default spark.memory.offHeap.size = 0<br>

Off-Heap Memory = Executor Memory (in Off-Heap) + Storage Memory (in Off-Heap)<br>
**Both are 50% each**

---
### 3. Overhead
---

spark.executor.memoryOverhead = max(384 MB, 10% of spark.executor.memory)


---
### Garbage Collection Process (GC)
---

GC Pressure: High garbage collection is one of the most common Spark performance problems. Watch the GC time in your Stage metrics. If GC is consuming more than 10% of task time, you have a memory problem. Switch to Kryo serialization, reduce object creation in UDFs, and consider using primitive arrays instead of boxed types.

spark.conf.set("spark.serializer", "org.apache.spark.serializer.KryoSerializer")

| Question                          | Answer                                                                                                         |
|-----------------------------------|----------------------------------------------------------------------------------------------------------------|
| Which memory does GC operate on ? | Only on-heap memory. GC has no visibility into off-heap or overhead memory — those are managed outside the JVM |
