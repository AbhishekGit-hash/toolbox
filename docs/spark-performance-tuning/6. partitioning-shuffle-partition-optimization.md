## Partitioning

### What Problems Does Partitioning Solve? 
1. `Fast Search (Query Performance)`: Spark will only process the relevant partition instead of the entire dataset (example above). This greatly reduces I/O and query execution time. 
2. `Parallelism / Resource Utilization`: Each core processes 1 partition; More number of partitions, more is the parallelism; again this does not mean we forcefully increase the number of partitions. Each partition should be `128MB` in size. 

### Partitioning Examples
1. Single/multi level partitioning
2. Using `repartition`/`coalesce` with `partitionBy` (controlling number of files inside each partition): 
    - `parititionBy` affects how data is laid out in the storage and is going to ensure that the output directory is organized into subdirectories based on the `value` given in `partitionBy`.  
    - Number of files in each `value` directory of `partitionBy` depends on the number supplied in the `repartition`/`coalesce`.


```python
from pyspark.sql import SparkSession

spark = (
    SparkSession.builder
    .config("spark.driver.memory", "10g")
    .appName("partition_app")
    .getOrCreate()
)

sc = spark.SparkContext()

# Reading a file
listening_activity_file = "../data/partitioning/raw/Spotify_Listening_Activity.csv"
df_listening_actv = spark.read.csv(listening_activity_file, header=True, inferSchema=True)

# Some operations on dataframe
```

### Modifying maximum number of bytes packed into a single partition

`spark.sql.files.maxPartitionBytes` controls the maximum number of bytes packed into a single partition when Spark reads files (Parquet, ORC, JSON, CSV etc.) from storage.<br>
Default: 128MB 

When to tune it:
**Increase it (e.g. 256MB) when:**

- You have too many small tasks and job is slow due to scheduling overhead
- Files are already large and you want fewer, chunkier tasks

**Decrease it (e.g. 64MB) when:**

- You have very large files and not enough parallelism
- Executors are running OOM because each partition is too big

```python
spark.conf.set("spark.sql.files.maxPartitionBytes", "134217728")  # 128MB in bytes

df_modified = spark.read.csv("../data/partitioning/raw/listening_activity.csv", header=True, inferSchema=True)
modified_partitions = df_modified.rdd.getNumPartitions()
print(f"Number of partitions with modified maxPartitionBytes: {modified_partitions}")
```


## Shuffle Partition Optimization

The most commonly misconfigured Spark parameter is `spark.sql.shuffle.partitions`, which defaults to **200**. This single number determines how many parallel tasks will process your shuffled data.<br>

With 200 partitions and a small dataset, you’re creating 200 tiny tasks — massive overhead.<br>
With 200 partitions and a 10TB dataset, you’re creating tasks so large they spill to disk.<br>

Problems:
- Slower completion time
- Under-utilization of cluster

### Scenario 1: Data per shuffle partition is large

Q. shuffle.write in Saprk UI = 300 GB. Cluster Config: 5 executor; 4 cores per executor.<br>

total cores = 5 * 4 = 20 cores<br>
spark.sql.shuffle.partitions = 200<br>
data per shuffle partition = 300 / 200 = 1.5 GB (Large Amount of Data)<br>

**Solution:**
**General rule: Target partition sizes between 100 MB - 200 MB.**<br>
number of shuffle partitions = 300 * 1000 / 200 = 1500<br>

Update shuffle partitions
```python
spark.conf.set("spark.sql.shuffle.partitions" , 1500)
```

### Scenario 2: Data per shuffle partition is small

Q. shuffle.write in Saprk UI = 50 MB. Cluster Config: 3 executor; 4 cores per executor.<br>

total cores = 3 * 4 = 12 cores<br>
spark.sql.shuffle.partitions = 200<br>
data per shuffle partition = 50 / 200 = 250 KB (Very Low Data)<br>

**`Approach 1:`**
Optimal size of partition  between 1 MB and 200 MB. Let's take 10 MB
number of shuffle partitions = 50 / 10 = 5

Update shuffle partitions
```python
spark.conf.set("spark.sql.shuffle.partitions" , 5)
```
**`Approach 2`**
Take all the available cores = 12
size of shuffle partition = 50 / 12 = 4.2 MB (Good number)

Update shuffle partitions
```python
spark.conf.set("spark.sql.shuffle.partitions" , 12)
```
